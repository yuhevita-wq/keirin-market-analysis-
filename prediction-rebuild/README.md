# Prediction Rebuild

オッズパーク / netkeirin などの文章付き予想を、結果を見る前に因果構造へ分解し、弱い接続だけを切断して最小限に再構築するための実験領域です。

既存のロードマップ、独自展開生成、買い目生成とは分離して扱います。

## 目的

1. 発走前の予想文章を保存する
2. 文章を因果鎖へ分解する
3. 壊す対象を「選手」ではなく「因果の接続」に限定する
4. 壊れなかった核を保持する
5. 元記事・別記事・選手コメント・並びに存在する材料だけで最小再構築する
6. 発走後に初めて結果を取得する
7. 切断・再接続・改悪・改善を評価する

## ディレクトリ

```text
prediction-rebuild/
├── raw/            # 取得した予想原文・URL・取得時刻
├── pre_race/       # 結果を見る前に固定した分解・切断・再構築
├── results/        # 発走後に取得した結果
├── evaluations/    # 切断成功・再接続成功・改善・改悪の評価
├── summary/        # 累積集計
├── schemas/        # JSONスキーマ相当の項目定義
└── templates/      # 新規レース登録用テンプレート
```

Gitは空ディレクトリを保持しないため、各領域には `.gitkeep` またはテンプレートを置きます。

## 最重要ルール

- `pre_race` は結果取得前にコミットする
- `pre_race` 作成時は結果ページを参照しない
- 独自の第三展開を自由生成しない
- 壊れていない核は変更しない
- 切断した先だけ再構築する
- 再接続材料は取得済み文章・選手コメント・並びに存在する情報に限定する
- 同一文章は2票として数えない
- オッズパークとnetkeirinの独立性はレースごとに判定する
- 着順的中だけでなく、因果接続単位で評価する

## 基本フロー

```text
raw
  ↓
文章重複判定
  ↓
因果鎖分解
  ↓
接続強度判定
  ↓
弱い接続を切断
  ↓
生存核を固定
  ↓
既存材料のみで最小再接続
  ↓
pre_race をコミット
  ↓
発走
  ↓
results
  ↓
evaluations
  ↓
summary
```

## 主要評価指標

- `core_survival`: 残した核が結果圏に残ったか
- `cut_success`: 切断した接続が実際に切れたか
- `reconnect_success`: 再接続した要素が実際に結果へ侵入したか
- `improved`: 元予想より再構築が改善したか
- `degraded`: 元予想より再構築が悪化したか
- `unchanged`: 元予想と再構築の評価が同等か

## 禁止

- 結果を見てから `pre_race` を書き換える
- 過去ロードマップのルールを自動流用する
- 「競輪では普通こう」で新しい接続を作る
- 全可能性を列挙して逃げる
- 買い目へ変換して評価を曖昧にする
