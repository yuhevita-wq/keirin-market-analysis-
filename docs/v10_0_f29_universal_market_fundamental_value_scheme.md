# v10.0-F29 — Universal Market × Fundamental Value Formation

## Status

**DESIGN FROZEN PRE-SIMULATION**

この文書はシミュレーション前の設計仕様を固定するためのもの。
`v10.0-F29` の結果は、この設計時点では一度も評価していない。

目的は「過去期間で当たった条件を残す」ことではなく、今後の未知レースにも同じ計算を適用できる普遍的な価値判定器を作ること。
利益・回収率を保証するものではなく、未見期間で再現性を検証するための固定仮説である。

## 1. 今までの成功から残すもの

### 完全市場を使う
- 3連複35通りを完全に使う。
- 3連単210通りを完全に使う。
- 欠損を推測補完しない。

### 市場の役割を「予想」ではなく「価格」にする
- 3連複市場は3車集合の支持を表す。
- 3連単市場は着順まで含めた支持を表す。
- 正規化市場支持と実オッズを分離する。
  - 正規化支持 = 市場がどこへ資金を置いているか。
  - 実オッズ = 控除を含んだ実際の購入価格。

### フォーメーションは構造として買う
- 個別車券の後付け削除をしない。
- 1着・2着・3着の支持階層から長方形フォーメーションを作る。
- 各位置の人数は事前固定しない。
- 支持の最大隣接段差を自然境界として使う。

### ラインを使う
- 楽天Kドリームスの予想並びを利用する。
- 出走表の自力/追込実績を、実際のライン位置に応じた `role_fit` に変換する。

## 3. Race-card Fundamental Layer

使用項目は結果前に出走表で確定する歴史スナップショットだけ。

- `score`
- `top3_rate`
- `b_count`
- `nige_count`
- `makuri_count`
- `sashi_count`
- `mark_count`
- `line_position`
- `line_size`

予想印・評価欄は使わない。

各数値は7車内で ordinal rank に変換する。

- 最強 = 1
- 最弱 = 0
- 同値は同値

自力適合:

`attack = mean(rank(B), rank(逃), rank(捲))`

追走適合:

`follow = mean(rank(差), rank(マーク))`

ライン役割:

- ライン先頭: `role_fit = attack`
- 2番手以降: `role_fit = follow`
- 単騎: `role_fit = mean(attack, follow)`

最終基礎評価:

`F(i) = mean(score_rank(i), top3_rank(i), role_fit(i))`

すべて等ウェイト。学習係数は持たない。

## 4. Fundamental ordered distribution

`F` を直接オッズ閾値と比較しない。
まず7車の順序確率分布に変換する。

7車を一般化した N 車レースとして、

`weight(i) = 1 + (N - 1) * F(i)`

とする。
7車なら自然に1〜7の範囲になる。

この重みから Plackett–Luce 型で3着までの順序分布 `R(t)` を作る。

`R(a,b,c)`
= aが1着となる重み比
× a除外後にbが2着となる重み比
× a,b除外後にcが3着となる重み比

210順列全体で正規化する。

---

## 5. 三つの独立視点を等ウェイト統合

### 3連複

35通りを正規化:

`P(c) = (1 / trio_odds(c)) / sum(1 / trio_odds)`

これは3車集合の市場支持。

### 3連単

210通りを正規化:

`Q(t) = (1 / trifecta_odds(t)) / sum(1 / trifecta_odds)`

これは正確な着順の市場支持。

### 出走表

前節の `R(t)`。

### Universal Blend

各3連単 t について、

`B_raw(t) = [ Q(t) * P(set(t)) * R(t) ]^(1/3)`

210通りで再正規化して、

`B(t) = B_raw(t) / sum(B_raw)`

とする。

つまり、
- 3連複市場
- 3連単市場
- 出走表基礎評価

を**1/3ずつ等しいログ重み**で統合する。
過去結果から重みを学習しない。

---

## 6. フォーメーション生成

`B(t)` から位置別支持を作る。

- `B1(i) = sum B(i,*,*)`
- `B2(i) = sum B(*,i,*)`
- `B3(i) = sum B(*,*,i)`

各位置で支持順に並べ、隣接支持比の最大段差を市場階層の境界にする。
同じ最大段差が複数ある場合は後ろの境界を採用し、不要に狭くしない。

生の上位集合を、

- `F1 = first upper tier`
- `F2 = F1 ∪ second upper tier`
- `F3 = F2 ∪ third upper tier`

として長方形フォーメーションにする。

個別の3連単をオッズや結果によって削除しない。

---

## 7. 購入判断は経済的ブレークイーブンだけ

ここで初めて実3連単オッズを価格として使う。

100円ずつフォーメーション全点を買うと仮定する。

推定期待払戻倍率:

`ExpectedReturn = sum[B(t) * odds(t) for t in formation]`

点数を Nticket として、

`EstimatedROI = ExpectedReturn / Nticket`

購入条件はただ一つ:

`EstimatedROI > 1.0`

1.0は過去結果から作った閾値ではなく、100%回収の自然な経済的ブレークイーブン。

- `EstimatedROI <= 1.0` → NO BET
- `EstimatedROI > 1.0` → フォーメーション全点を等額購入

個別券のEV判定による削除は禁止。

## 9. レース種別の位置づけ

レース種別は分析ラベルとして保存するが、v10本体には入れない。

したがって同じ市場・出走表構造なら、

- 予選
- 一般
- 準決勝
- 選抜
- 特選
- 決勝

のどれでも**完全に同じ買い目計算**になる。

将来、レース種別で成績差が出ても、その結果を見て本体を分岐させることはしない。
まず「普遍モデルとして差がなぜ出るか」を診断する。
