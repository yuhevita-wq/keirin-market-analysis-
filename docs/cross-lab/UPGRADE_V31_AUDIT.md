# v3.1：奈良の誤採用を生んだ原因と修正

対象は2026-10-15朝の奈良3R・4R・10R・11R・12R。結果を使わず、撤回した事前答案と同じ入力で監査した。

## 原因

1. v3はすでに42通りの順序付き1・2着を正規化していた。「個々の勝率を掛けた」「2人とも1着と計算した」という説明はコード上の原因として不正確だった。
2. ペアのロジットは個人特徴の加算35項と相互作用18項。相互作用があること自体を、同時残存を識別できた証明として扱った。後続検証の回収率はA級63.8%、S級72.1%で、相互作用なし比較より下だった。
3. `compareJointForecast`はクロス候補内の最大値を`selectedSignature`に入れ、`resolveDecision`が無条件に「主採用」へ変換した。筋・選外車の確率も計算していたが、選択集合の外だった。全候補が不適切でも必ず1型を採用した。
4. 相手が勝つ場合の2着競合を表示せず、私が順位に合わせた展開説明を後付けした。決まり手の個別実績は、その2人が同時に残る証拠ではない。
5. 既存テストの「勝率周辺分布が同じでも同時確率が違う」は人工分布の集計テストだった。実際に出した奈良の推奨が成立条件を満たす検証ではなかった。

## 奈良10Rの具体例

同じv3の出力で、17のどちらかが1着になる確率は53.45%、2人で1・2着になる確率は7.73%、基本4点は6.09%。異なる事象であり足し替えない。

|勝者を固定した条件|クロス相手の2着|他の2着競合|
|---|---:|---|
|⑦が1着|①13.09%|同線②63.96%|
|①が1着|⑦16.62%|同線⑤40.74%、別線②26.10%|

相互作用なし比較モデルの基本4点は7.16%、v3は6.09%（−1.07ポイント）。同時残存を弱める出力にもかかわらず、候補内1位を主採用に変換していた。これらはモデル内の数値であり、実際の確率や因果効果の証明ではない。

## 実装した修正

- 順位は`rankedSignature`、採用は`selectedSignature`として分離。現行の実験モデル・外部予測JSONとも順位だけから自動採用しない。外部JSONの自称検証済みフラグでも解除できない。
- 各候補について「どちらか1着」「2人で1・2着」「1人だけ2着以内」「2人とも2着外」を分離表示する。後ろ3区分は互いに排他的で合計1。
- 表裏ごとに全6車の条件付き2着確率、クロス相手の順位、同線競合、基本2点確率を表示する。
- 同じ学習条件で別途学習済みの相互作用なしモデルと比較し、個人能力の加算に対して何が変わったか表示する。差分を因果効果や成立証明とは呼ばない。
- 分析者が主採用する場合にも、表裏それぞれの「勝つ走りで相手が残る理由」「同線番手を含む2着競合」の記録を必須にする。文章が埋まったことを統計的な検証済みとは扱わない。
- 基本4点、全12候補、括弧補助、横棒参考は維持。先頭同士の一律禁止・番手優遇・手作業の減点・確率しきい値は導入しない。

## 検証と限界

奈良の入力は`fixtures/nara_20261015_withdrawn.json`に事前答案撤回の監査用として保存。結果や払戻を含めず、学習にも使わない。元の係数・確率は変更していない。

追加テストは、同じ「どちらか勝つ」が同時入着0%/100%を取りうる例、奈良10Rの2着競合、全5Rの自動採用停止、旧フィールドによる採用回避の防止、表裏片側だけの記録拒否、全12候補・210確率の維持を検証する。

**今回直したのは、未検証の順位を採用へ変換する欠陥と、競合を見落とす評価経路。予測精度・回収率の改善を達成した修正ではない。** モデルを再学習しておらず、新たな回収率を名乗らない。今後のモデル更新は、時系列を分離した3–2–2の型選択・方向別2着・市場比較で改めて検証する必要がある。
