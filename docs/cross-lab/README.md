# CROSS LAB – 異線成立条件判定 (cross-interaction-v1)

## なぜ作り直したか

従来の「競走得点・Bが高い選手を並べる → クロスの形に整形する」は、クロス成立条件を予測していない。この実装ではその処理を禁止する。

## クロス4点は変更しない

選ぶのは異なる2ラインの各2車。1着・2着は各線1名ずつ（表裏）、3着は選んだ残りの2車。例：`13-13-24` = `1-3-2 / 1-3-4 / 3-1-2 / 3-1-4`。

- 最初から3着を独立のランキングで決めない。
- 同じラインの2選手を1/2着クロスとして選ばない。
- 3–2–2の2車×2車クロスでは、選外の3車ラインが全滅する必要を必ず提示。
- 3車側から追加する従来の特殊拡張はコア4点の定義とは別モジュール。ここでは自動実行しない。

## 選択基準

【成立条件を持つ異線の1/2着組だけを候補化】。実装したメカニズムは：
1. 一線の先行実績（Bと逃げ）×他線の捲り実績
2. 一線の先行からの番手差し×他線の捲り
3. 一線の先行×他線捲りの番手差し

さらに選外3車を個別に検査し、強い競合・3車ライン全滅・他ライン全滅という反証を付ける。得点はUIの選定に一切使用しない。Bだけでも発火しない。弱い決まり手も0とみなさず1件から検査する。

**重要：** 上記は物理的に成り立ち得る構図の限定的な仮説であって、過去結果から較正済みの勝率モデルではない。該当候補を強制的に一つに絞らず、同評価や未取得データは保留する。回収率や利益優位性についてはまだ判定しない。

## 出走表と取得できる情報

`index.html` は楽天Kドリームスの `/racedetail/{race_id}` を受け取り、リポジトリ内 `docs/keirin-shogi/live-race-data.json` のキャッシュを参照する。対象外URLを外部スクレイピングできると偽らない。キャッシュ未収録なら手入力に切り替える。

読み取った並びを入力で修正可能。選手ごとに逃・捲・差・マの値を入力可能。空欄は**欠損**、0ではない。出走表に決まり手が入っていなければ自動推奨しない。

3連単オッズは任意入力。入力されれば参考表示のみ。オッズがなければ市場評価不可。逆オッズ正規化やライン別の過去確率を個々のクロス4点の的中確率として転用しない。

## 起動とテスト

- GitHub Pages 上の `docs/cross-lab/index.html`（Pages側で`docs`公開が設定されている場合）
- エンジン: `cross_engine.mjs`
- テスト: `node --test docs/cross-lab/cross_engine.test.mjs`
- ブラウザーから必要なのは `index.html` と同ディレクトリの `cross_engine.mjs`、既存のキャッシュだけ。

## 公開先についての正確な区別

GitHub リポジトリの `docs/cross-lab/` に実装・保存したことと、別サービスで公開中の `https://keirin-cross-lab.kuwawa01.chatgpt.site` を変更したことは異なる。ChatGPT Site の編集・公開はこのコミットでは行っていない。

## 未完了の検証

過去レースの出走表時点特徴から成立条件を再現し、時系列を分割して的中頻度・利益・偽陽性・3車ライン選外を計測する必要がある。その前に「高配当を狙えるクロス選別が完成した」と宣言しない。
