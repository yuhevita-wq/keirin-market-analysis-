# Prediction Engine v1

競輪の過去データから、未来のF1・S級・7車立てを**事前情報だけで予測し、買うレース・見送るレース・3連単買い目を機械的に決める**ための新エンジン。

旧v6.1の微修正ではなく、予測・検証・購入判断をゼロから分離した別系統の実装。

## データの役割

- 2024Q1-Q2: 予測モデルの初期学習
- 2024Q3: 購入ルール選択専用
- 2024Q4: 選ばれた1ルールだけを検証する不可逆ゲート
- 2025H1: Q4合格時のみ開く破壊試験前半
- 2025H2: H1予測をすべて固定した後、H1までの履歴だけを追加して破壊試験後半
- 2026H1: 封印。v1では開封コマンド自体を提供しない

2024Q4の結果を見て別の購入ルールへ乗り換えることは禁止。Q4ゲート不合格なら2025は開かない。

## 入力

### 予測に使用する事前情報

`races.csv` / `entries.csv` から、発走前に公開される情報のみを使う。

- 競輪場
- レース番号
- レース種別
- 車番
- 年齢
- 級班
- 脚質
- ギヤ
- 競走得点
- S/B
- 逃・捲・差・マ
- 1着/2着/3着/着外回数
- 勝率・2連対率・3連対率
- 並び予想
- ラインID、ライン位置、ライン人数
- 対象期間より前の結果だけから構築した過去対戦・過去連係履歴

### 予測・購入判断に絶対使用しない情報

- `results.csv`
- `payouts.csv`
- `trifecta_final_odds.csv`
- `trio_final_odds.csv`
- 対象レース以後の情報

結果と払戻は、予測と買い目を固定した**後**の採点にだけ使う。

## 予測の3層

### 1. Statistical / pairwise

7車なら1レース21組の選手ペアを作る。

各ペアについて、得点差、B/S差、決まり手差、ライン位置差、ライン強度、レース番号、競輪場、レース種別、脚質、級班、ライン形などを特徴量にする。

ロジスティック回帰で `AがBより先着する確率` を学習し、21組の確率を7選手の潜在強度へ戻す。

### 2. Relationship

対象時点より前の履歴だけで、選手同士の

- 過去対戦数
- 先着率
- 同一ライン連係数
- 同一ライン時の2人同時3着内率

を持つ。

少数標本をそのまま信用せず、ベイズ型の縮小推定で0.5へ戻す。1戦1勝を100%扱いするような人類の悪癖は採用しない。

### 3. Similarity

過去レースを匿名の構造へ変換する。

例: `L1P1` は「先頭得点が最も高いラインの1番手」。選手名そのものではなく役割で比較する。

まず同じレース種別を優先し、次に同じライン数を優先する。標本が不足した場合のみ条件を段階的に緩める。

## 210通りへの変換

Pairwiseモデルから得た7選手の潜在強度をPlackett-Luce分布へ変換し、7P3 = **210通りすべて**の3連単確率を作る。

Similarityモデルの3連単分布と統合し、最終的に

- 各選手1着確率
- 2着内確率
- 3着内確率
- 3連単210通り確率
- 確率分布のエントロピー
- 上位3/5/10点への確率集中度
- StatisticalとSimilarityの不一致度

を出す。

## 買う・見送る

買い目決定に確定オッズは使用しない。

購入ルールは次の情報だけを見る。

- 3連単分布のエントロピー
- 上位10点への確率集中度
- 2モデルのTotal Variation距離
- 上位買い目の累積予測確率
- 最大購入点数

100円均等購入で採点し、ROIだけでなく購入率、的中率、最大ドローダウン、最大連敗、月別安定性を記録する。

## 2024開発手順

1. Q1+Q2で予測モデルを学習
2. Q3だけで事前定義済み243通りのTicketPolicyを比較
3. Q3で1つだけ選択して固定
4. その1つだけをQ4へ適用
5. Q4ゲートを判定

Q4ゲート:

- 購入60レース以上
- Q4全体ROI 1.00以上
- `月15レース以上購入かつ月ROI 0.85以上` が3か月中2か月以上

1つでも満たさなければ2025破壊試験は禁止。

## 2025破壊試験

Q4ゲート合格時だけ実行できる。

- 統計モデルの係数は2024で固定
- 購入ルールも2024で固定
- 2025H1を一括予測してから採点
- H1終了後にだけ、H1結果をRelationship/Similarityの履歴へ追加
- 係数・閾値は変更しない
- H2を予測・採点

つまり半期ごとの保存運用と同じ時間解像度で、実戦時に存在する履歴だけを追加する。

## 2026H1

封印状態。

`DatasetCatalog`ではsealed validationとして定義し、`load_labels()` / `load_payouts()` は明示解除なしで例外になる。さらにv1 CLIには2026を開くコマンドを置いていない。

2025を見てv1を修正した場合、その修正版が完全固定されるまで2026は触らない。

## 実行

依存関係:

```bash
python -m pip install -e ".[prediction,dev]"
```

ユニットテスト:

```bash
pytest -q tests/test_prediction_engine.py
```

封印状態確認:

```bash
keirin-prediction-engine-v1 manifest
```

2024開発だけ:

```bash
keirin-prediction-engine-v1 calibrate-2024 --root . --out artifacts/prediction_engine_v1
```

Q4ゲート合格時に2024→2025まで自動実行:

```bash
keirin-prediction-engine-v1 develop-and-test --root . --out artifacts/prediction_engine_v1
```

単独で2025を実行する場合も、`2024_selected_policy_and_q4_gate.json` 内の `q4_gate.passed=true` が必須。単なるTicketPolicy JSONではロックを解除できない。

## 主要ファイル

- `prediction_schema.py`: データ区分、情報漏洩防止、2026封印
- `prediction_features.py`: 相対特徴、ライン構造、過去対戦・連係
- `prediction_models.py`: Pairwise、Similarity、210通り確率化
- `prediction_strategy.py`: 買う/見送る、採点、243候補の固定グリッド
- `prediction_engine.py`: 予測司令塔、半期履歴更新
- `prediction_cli.py`: 2024開発、Q4ゲート、2025破壊試験の実行制御
- `.github/workflows/prediction-engine-v1.yml`: テストと手動フルシミュレーション
